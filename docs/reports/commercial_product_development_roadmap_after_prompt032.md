## 2. 現状プロダクトの実態

### repo-verified capabilities [実]
- 多形式取込 PDF/DOCX/XLSX/CSV/PPTX（`rag_core/document_converters/*`）。

- 出典付き根拠回答＋`too_general` 非回答ガード（`rag_core/qa.py`、実ベクトル校正済）。
- テナント分離（メタデータ＋`_tenant_matches`）。**再起動/ハッシュ検証リストア越しに分離維持を検証**
  （`tests/test_durable_multitenant_persistence.py`）。
- API キー→テナント認可（フェイルクローズ, `webapi/api_auth.py`）、管理/デバッグ経路保護。
- レート制限（プロセス内, 既定オフ）、`/metrics` JSON+Prometheus、監査ログ。
- deploy smoke / backup / restore（ハッシュ検証）/ TLS 参照、ドライランオンボーディング＋
  インポートマニフェスト、限定ベータ一式。テスト 719 件 green [実]。
- `production_safe` プロファイル、`/chat`・`/chat/stream` 既定オフの per-tenant プロファイル
  ランタイム結線（`CHAT_USE_TENANT_PROFILE`）[実]。

### beta-ready capabilities [実]
- 限定外部ベータは **GO（条件付き）**（`beta_go_no_go_assessment.md`）。チェックリスト/
  ロールバック/オンボーディング Runbook/`limited_beta_preflight.sh` 完備。

### commercial gaps（売るのに足りない）[実]
- **エンドユーザ向け本番チャット UI 不在**（`product-preview`/`admin/review` HTML のみ）。
- **SSO/AD 連携なし**、非エンジニア向け管理コンソールなし。
- 監視/アラートは**文書のみ・未配線**。ロールバック/デプロイ後 smoke は手動。
- 顧客実績/ロゴなし（小規模ベンダーとしての信用補強が未整備）。

### not production-ready areas [実]
- 単一ノードローカル Chroma（HA/水平スケールなし）。
- `production_safe` は LLM 生成回答を無効化＝自由会話 AI ではない（高精度検索＋承認回答＋非回答）。
- Prompt030 で表面化: `_build_base_where` の複数キー `where` を現行 Chroma が `$and` 必須で
  拒否（非既定テナントのベクトル検索に影響）。
- 大規模実日本語業務文書での精度/レイテンシ/コストは**未測定** [不明]。

## 5. ユースケース定義（最初の 5 つ）

凡例 対応度: ◎ほぼ対応 / ○条件付き / △要追加（[実] 基準）。

1. **手順書 QA（作業手順の即答）**
   - ユーザーストーリー: 生産技術者が「○○工程の段取り替え手順は？」と聞く。
   - 入力文書: 手順書 PDF/Word、チェックリスト Excel。
   - 回答スタイル: 手順を箇条書き＋**出典（文書名/ページ）**。
   - 引用が重要な理由: 現場が原典を確認して実行できる。
   - 不確実時: `too_general`/根拠不足で**「該当手順が見つかりません」**と非回答 [実]。
   - 対応度: ◎（UIのみ△）。 不足: エンドユーザ UI。

2. **規程・標準 QA（言い切り回答）**
   - ストーリー: 品質管理者が「外観検査の合否基準は？」と聞く。
   - 入力: 承認済み Q&A（規程から整備）＋規程 PDF。
   - 回答: 承認済み完全一致の**決定論的回答**＋出典 [実]。
   - 引用: 監査・トレーサビリティ。 不確実時: 承認外は候補提示 or 非回答。
   - 対応度: ◎（承認 Q&A 整備運用が前提）。 不足: 承認 Q&A 作成支援 UI。

3. **トラブルシューティング（過去事例検索）**
   - ストーリー: 設計者が「××アラーム発生時の対処事例は？」と聞く。
   - 入力: 過去トラブル報告（PDF/Excel/PPT）。
   - 回答: 類似事例＋対処＋出典。 不確実時: 非回答/候補のみ [実]。
   - 対応度: ○（事例コーパス品質依存）。 不足: 大規模実文書での精度実証 [不明]。

4. **品質・安全マニュアル QA**
   - ストーリー: 現場リーダーが「保護具着用の規定は？」と聞く。
   - 入力: 安全規程・教育資料。 回答: 規定＋出典、危険時は断定回避。
   - 対応度: ◎（モバイル/現場 UI △）。 不足: 現場向け軽量 UI。

5. **情シス社内ヘルプデスク**
   - ストーリー: 社員が「VPN 接続申請の手順は？」と聞く。
   - 入力: 申請手順・IT FAQ。 回答: 手順＋出典、フィードバック収集 [実：`/chat/feedback`]。
   - 対応度: ◎（UIのみ△）。 不足: UI、有人エスカレーション導線（`admin/review` は有 [実]）。

## 10. まだ作らないもの（理由付き）

- **フル SaaS マルチテナント課金**: 最初は単一部門オンプレ。需要未実証で過剰投資。
- **高度な管理コンソール**: PoC は最小運用で足り、UI 投資は端末側を優先。
- **公開マーケットプレイス**: B2B 直販フェーズで不要。
- **モバイルアプリ**: まず Web UI。現場用途は後続（軽量 Web で代替）。
- **独自 LLM 学習**: 差別化は検索/ガード/承認回答であり学習ではない。コスト過大。
- **クロスエンコーダ昇格**: モデル未キャッシュ・既定オフ。昇格判断は保留 [実]。
- **HA クラスタ**: 単一部門/単一拠点 PoC では不要。Phase 3 で検討。
- **複雑な RBAC UI**: PoC は単純権限で十分。
- **公共調達対応機能**: 調達/監査要件が重く、最初の 1 社には不向き [調]。
