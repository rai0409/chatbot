# ロードマップ（社内導入 → SaaS）

更新: 2026-10-29。この文書は、決定事項と進捗を残すためのものです。決定は、根拠と条件とともにここに記録します。

## ゴール

- **直近:** 社内（閉域、または LLM のみ外部接続）で使える、根拠付きの問い合わせシステムを、限定試用から本番運用に乗せる。
  平日 8〜21 時、稼働率 99.0%、LLM の障害時は抽出型の回答で継続する（障害は利用者と管理者に見える形で表示する）。
- **品質:** 実データの質問票で、誤受理率 1% 未満（失敗 0・299 件が目安）。根拠付きで回答し、根拠がなければ「答えられません」。
- **将来:** SaaS（顧客別の分離・課金・上限・SLA、第三者のセキュリティ診断）。

## 決定事項

| 項目 | 決定 | 詳細 |
|---|---|---|
| 運用形態 | LLM のみ外部接続。Graph・Outlook・メールなどは、設定でオン・オフ（既定オフ）。外部連携なしで全機能が動くことを先に保証する | `operations/integrations.md` |
| 権限 | ソース単位の「見られる／見られない」（文書単位は不要） | S4 以降 |
| 稼働率 | 平日 8〜21 時、99.0%。LLM 障害は表示したうえで、抽出型で答えられれば稼働とみなす | — |
| 回答の構成 | 検索（ハイブリッド）→ 抽出 → LLM が根拠の範囲で回答 → 検証。確実に同じ質問は承認済み QA で LLM なし。縮退時は抽出型 | `operations/llm_gateway.md` |
| **LLM（ローカル）** | **Qwen3 系の 8B 級（量子化）、16GB 以上の GPU なら 14B 級**。Ollama / vLLM の OpenAI 互換 API | `operations/llm_model_selection.md` |
| **LLM（クラウド・廉価）** | **OpenAI の最新の小型・低価格クラス**（名称は着手時に公式で確認）。Claude は、ネイティブ API アダプターの後に候補として比較 | 同上 |
| 採用の条件 | 実データの質問票で、LLM なしと比べて正答率が下がらず、誤受理率が基準内であること。満たさなければ次点に差し替える | 同上 |
| 設定の置き場 | 秘密は環境変数、配備固有は `.env` と配備ごとの設定ファイル、実行時はコンソールのスイッチ。コードに固定しない | `operations/configuration.md` |
| 管理画面 | React（SPA）。サーバ側のレンダリングは使わない。本番に Node を置かない。依存は固定版・公開から 14 日以上・インストール時スクリプト無効 | `webui/README.md` |
| 資料の順序 | 管理画面を完成させてから、運用手順書などの資料を作る | — |
| 保持期間の既定値（案、設定で変更可） | 会話履歴 90 日、評価用の記録 365 日、監査ログ 365 日、使用量・状態遷移 13 か月 | S3 で実装 |

### S1・S2 で入ったもの

- 固定値の設定化（Graph の URL・スコープ、タイムアウト、OIDC の待機、埋め込みの接続先）。既定は従来と同じ。
- `rag_core/runtime_settings.py`（理由つき・監査つきの実行時スイッチ）、`rag_core/integrations.py`（3 層）、出口の送信関数でのチェック。
- `webapi/routers/`（ルーター基盤）、`/admin/system/*`、`/system/status`、`/console/`（React コンソールの配信）。
- `webui/`（Vite・React・TypeScript。固定版、`npm audit` 0 件、型検査・テスト・ビルド済み）。
- `rag_core/llm_gateway.py`・`llm_profiles.py`・`circuit_breaker.py`・`llm_usage.py`。回答生成と書き換え・検証・採点が、すべてゲートウェイを通る。

### S3〜S5 で入ったもの

- `rag_core/records.py`（記録レベル、判定、フィードバックの結合、保持期限の処理）、`webapi/records_hook.py`（チャットの 3 経路から呼ぶ。失敗しても回答は止まらない）。
  記録の既定はオフ。環境の上限（`RECORD_LEVEL_MAX`）を超える設定は、コンソールからはできない。読むこと自体を監査ログに残す。
- `rag_core/golden_store.py`（コンソールで編集するゴールデン QA。評価が読む形で書き出せる）、`rag_core/audit_view.py`（監査ログの閲覧と検証）、
  `llm_usage` の営業時間の停止時間と日別集計。
- 管理 API：`webapi/routers/` の `records`・`golden`・`usage`・`audit`・`governance`（提案・版・評価台帳・設定項目・監視）・`access`（`operations/admin_api.md`）。
- 画面：サイドバーつきのコンソールに、14 画面（`operations/console.md`）。回答画面には、AI が使えないときの帯と回答ごとの注記。
- 人が責任を持つ操作は、操作者の名前の申告を求める（本人確認ではない。SSO の本人識別子への置き換えは未実装）。

### 評価後の追加（S6 の前に実施）

- 既存の管理系ルート（文書取込・契約・抽出・ソース・シノニム、約 800 行）を `webapi/main.py` から `webapi/routers/` へ移設（3785 行 → 2986 行。ルートの一覧は移設の前後で同一）。
  ログイン・レビュー・ダッシュボード・チャット・OIDC の部分は、テストとの結びつきが強いため残してある。
- **ゴールデン QA の評価への接続**：`scripts/tenant_eval.py evaluate --golden-source profile|console|both`（`operations/tenant_evaluation.md`）。
- **1 日の上限**（利用者・テナント・全体）、**モデルのティアの割り当て**（全員・テナント・役割・1 人）、**バッチ呼び出し**（同期と、プロバイダのバッチ API）、
  LLM のアラート信号、回答の「上限に達した」注記、コンソールの「上限とモデルの割り当て」画面（`operations/llm_limits.md`）。
- バックアップの対象に、設定・記録・使用量・ゴールデン QA・評価台帳・プロファイルの版・ソース・契約・抽出を追加（これまで入っていなかった）。
- 「通知と監視」「上限」「質問者の識別」を担保する計画：`operations/assurance_plan.md`。

### 未着手・持ち越し（S1〜S5 の範囲のうち）

- **回答画面の React 化**（今は従来の HTML に帯を足しただけ）。従来の管理画面（`/admin/...`）は残してあり、ナビから新コンソールへ行ける。移設して消すのは、ブラウザでの確認の後。
- ダッシュボードの自動更新（従来は 30 秒ごと）。画面の英語のサーバーメッセージの日本語化（一部は、サーバーの文言をそのまま表示している）。

- 権限の確認は読み取りのみ（利用者とグループは、ID 基盤と環境の設定で管理する）。

- （S7 で実装済み、実環境の確認待ち）ブレーカー状態の Redis 共有、外部連携のオンの二人承認、Claude 用のネイティブ API アダプター、サービス停止の外部監視（`operations/external_monitoring.md`）。
