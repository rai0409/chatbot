# 生成された回答の文単位の根拠検証（`rag_core/grounding.py`）

既存の `validate_output` は「箇条書きが、引用した根拠と語を 1 つ共有する」ことしか見ない。
`GROUNDING_VERIFY_ENABLED=true`（既定 `false`）のとき、**LLM が生成した回答の各文**が、引用した根拠に支えられているかを確かめ、
支えのない文を取り除く。抽出式の回答（文書の文をそのまま引用）には要らないので適用しない。

## 規則

| 種類 | 規則 | 破った文 |
|---|---|---|
| 厳格 | `numbers`: 文中の数字がすべて、引用した根拠にある | 削除（LLM の再判定なし） |
| 厳格 | `identifier`: 英字の語がすべて根拠にある | 削除 |
| 厳格 | `katakana`: 3 文字以上のカタカナ語がすべて根拠にある | 削除 |
| 厳格 | `new_term`: 3 文字以上の漢字の語がすべて根拠にある | 削除 |
| 厳格 | `no_citation`: 実在する根拠の番号を 1 つ以上引用している | 削除 |
| 緩い | `coverage`: 文の内容語の `GROUNDING_MIN_COVERAGE`（0.5）以上が根拠にある | 削除。ただし LLM の機能 `verify` が許可されていて、LLM が `{"supported": true}` と答えれば残す |

- LLM に聞くのは、**緩い規則だけを破った文**に限る。拒否（ポリシー）・失敗・読めない応答は「支えられていない」として削除する。
- 取り除いた後に箇条書きが 1 つも残らなければ、抽出式の回答に置き換える（`validate_output` が失敗したときと同じ退避先）。
- `grounding.stats()` が確認数・削除数・救済数を数える（文は記録しない）。
- ノブ `GROUNDING_VERIFY_ENABLED` と `GROUNDING_MIN_COVERAGE` は登録済みで、回答キャッシュのキーにも入る。
  効果は `tenant_eval.py evaluate --knob GROUNDING_VERIFY_ENABLED=true` で、LLM 生成の回答の誤受理率を比べて確かめる。

## 限界

- 規則は表層の照合で、論理の誤り（根拠の言い換えで意味が変わる、条件の取り違え）は見えない。数値・固有名詞・語の有無の
  取りこぼしを減らすための安全網で、正しさの保証ではない。
- 文を取り除くので、回答が短くなることがある。取り除きすぎないか（合格率の低下）も同じ評価で確認する。
