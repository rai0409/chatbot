# 抽出レビュー（OCR の行の確認と補正）

6-1 で保存した OCR の行のうち、**信頼度の低いもの**を人が確認し、直した結果を**次の取り込みでインデックスに反映**する。

## 対象と判断

- `review_items`: 信頼度が `EXTRACTION_REVIEW_MAX_CONFIDENCE`（既定 80）未満、または信頼度が無い行。**低い順**。
  判断済みの行は既定で出さない（`include_reviewed` で出せる）。
- 判断は 2 種類:
  - **補正**（`submit_correction`）: その行の文字を別の文字に置き換える。OCR の文字と同じなら受け付けない（→「そのまま正しい」を使う）。
    1〜2000 文字、制御文字なし。
  - **確認**（`confirm_line`）: OCR の文字はこのままで正しい。
  - どちらも「誰が・いつ」を記録する。`revert` で判断を取り消せる。

## 判断は再取り込みで消えない

判断は、記録のとなり（`<キー>.corrections.json`）に、**（ページ, その行の OCR の文字）**をキーに保存する。行の ID や
ファイルのハッシュには結びつけない。そのため、取り込みのたびに記録が作り直されても、また新しい版のファイルでも、
**同じ行が同じ文字で読み取られる限り**、判断は引き継がれる。

## インデックスへの反映

- PDF の変換中、OCR（ページ全体のフォールバック）したページで、補正した行の文字を**最初の 1 か所だけ**、補正後の文字に
  置き換えてからチャンクに切る。インデックスには補正後の文字が入る。
- ページにその文字がもう無ければ「未対応（unmatched）」として数える（変換レポートの `corrections: {applied, unmatched}`）。
  補正ファイルが無い・壊れている場合は何も変えない（変換は失敗しない）。
- **反映には再取り込みが要る**。登録したソースの文書は `request_reingest`（`source_apply.mark_for_reingest`）が、
  反映済みマニフェストからそのファイルを外し、次の plan が「追加」として取り込み直す（大量変更ガードの対象にはならない）。
  手でアップロードした文書は、もう一度アップロードする。

## 限界

- 置き換えは文字列の一致による。OCR の行が、ページの文章の中で行をまたいで結合・整形された場合は一致せず、未対応になる。
- ページ内の画像だけを OCR した結果と、テキスト層のあるページは対象外（6-1 と同じ）。
- 補正は OCR の誤りを直すもので、文書の内容そのものの誤りを直すものではない。
