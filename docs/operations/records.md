# 質問・回答の記録（評価用）

利用者の質問と、システムの回答、その回答が正しかったかを、評価と改善のために残す仕組みです（`rag_core/records.py`）。
**行動の監視ではありません。** 誰が何を聞いたかを見張る目的では使いません。従業員の利用の記録にあたるため、**既定はオフ**で、オンにする前に利用者への周知と、読める人の決定が必要です。

## 記録レベル

| レベル | 残るもの | 使いどころ |
|---|---|---|
| オフ（既定） | 何も残さない（ダッシュボードのカウンターは数える） | 運用の標準 |
| 匿名 | 回答の種類、回答しなかった理由、出典の件数、応答時間、時刻。質問者は**ソルト付きのハッシュ**。質問・回答の本文は残さない | 利用状況の把握だけでよいとき |
| 通常 | 上に加えて、質問者の識別子（キーの指紋。SSO ならひとりにひとつ、名前ではない）、**質問、回答、出典**（メールアドレスは `[email]` に置換。数字は残す） | 評価の質問票づくり、誤りの調査 |
| 詳細 | 上に加えて、**リクエストの IP アドレスとブラウザ**。保持は短い（既定 30 日） | 不具合の調査など、期間を限るとき |

- レベルは、**全体**と**テナントごと**に設定できます（管理コンソールの「記録とレビュー」→「記録の設定」。**理由が必須**で、監査ログに残る）。
- **環境の上限**（`RECORD_LEVEL_MAX`、既定は「通常」）を超えるレベルは、コンソールからは設定できません。「詳細」にするには、環境の設定を変えます。上限を下げると、すぐに効きます。
- 数字を伏せないのは、条番号や金額が評価に必要なためです。メールアドレスだけを伏せます。
- 監査ログの質問の保護（`AUDIT_QUESTION_MODE`）と、会話履歴（利用者本人の履歴）は、これとは別の仕組みで、そのまま動きます。

## 誰が読めるか

- 管理者だけです。**テナントの管理者は、自分のテナントの記録だけ**を読めます（他のテナントの記録は「存在しない」ように見える）。
- **読むこと自体が監査ログに残ります**（一覧を開いたとき、1 件を開いたとき、判定したとき）。

## 判定とフィードバック

- 利用者が回答画面で押した 👍👎 と理由・コメントは、記録に**自動でひも付きます**（リクエスト ID とトレース ID で結合）。
- 人が記録を見て、**正しい／部分的に正しい／誤り**を判定します。「正しい」以外は、理由（出典が違う、情報が古い、根拠のない記述、情報が足りない、曖昧、その他）かメモが必須です。
  判定者の名前を入力します。名前は申告で、認証ではありません（記録と監査ログに残る）。
- 判定は記録とは別の行（`reviews.jsonl`）に残るので、**記録が匿名化されても残ります**。最新の判定が有効です。
- 判定した記録から、**ゴールデン QA** を作れます。「正しい」なら回答が、「誤り・部分的」なら判定者が書いた期待する回答が、基準（`reference`）になります。
  利用者の質問は、そのまま質問票になるので、**個人情報が含まれていないか、作った後に確認して直してください。**

## 保持と期限切れの処理

| 設定 | 既定 | 意味 |
|---|---|---|
| `RECORDS_RETENTION_DAYS` | 365 | この日数を過ぎた記録は、期限切れ |
| `RECORDS_DETAILED_RETENTION_DAYS` | 30 | 詳細レベルの IP・ブラウザは、この日数で消す |
| `RECORDS_EXPIRY_ACTION` | `anonymize` | 期限切れの扱い。`anonymize`＝本文・出典・質問者を消し、件数などは残す。`delete`＝その日のファイルを消す |
| `LLM_USAGE_RETENTION_DAYS` | 400 | LLM の使用量のファイルの保持（13 か月） |

**自動では消えません。** 管理コンソールの「保持の処理」（または `POST /admin/records/purge`）を実行したときだけ処理されます。
**既定は予行（何が処理されるかを見るだけ）** で、実行は確認のうえで行います。定期的に行うなら、同じ API を定期ジョブから呼びます。
監査ログは、ハッシュ連鎖を保つため、ここでは消しません（ローテーションされたファイルの保管・退避は運用で決める）。

## 保存先

`RECORDS_DIR`（既定は `runs/records`）に、日ごとのファイル `records-YYYY-MM-DD.jsonl`、判定の `reviews.jsonl`、匿名レベルのソルト `.salt` があります。
保存先のディスクは暗号化し、アクセスを管理者に限ってください。ソルトを環境変数 `RECORDS_HASH_SALT` に置けば、ファイルは作られません。

## 運用前に決めること

- 利用者への周知の文面と、規程上の位置づけ（人事・法務の確認）。
- 読める人（管理者のうち誰か）と、判定を担当する人。
- 評価の期間だけ「通常」にし、終われば「匿名」か「オフ」に戻す、といった運用ルール。
