# 複数クエリ検索（multi_query）

質問を言い換えた検索文でも検索し、結果を順位融合（RRF）でまとめる。`MULTI_QUERY_ENABLED=true` のときだけ動く
（既定 `false`）。評価してから顧客ごとに有効にする。「もっと詳しく調べる」（`deep`）の依頼では、その 1 回だけ有効になる。

## 変種（モデルは使わない。規則だけ）

| 種類 | 内容 |
|---|---|
| `original` | 質問そのまま（常に 1 つ目） |
| `cleaned` | 言いよどみ・依頼/疑問の語尾を取り除いたもの（前処理の口語規則） |
| `core_terms` | 重要語だけを空白でつないだもの |
| `synonym` | 質問中の語を、RAG プロファイルの同義語（有効な項目）の別の語に置き換えたもの |

検索する本数は `MULTI_QUERY_MAX_VARIANTS`（質問を含む総数、1〜5、既定 3）。deep では 3 以上にする。

## 融合とスコア

- 質問自身の検索（従来の 2 パス）と各変種の検索の結果を RRF（`MULTI_QUERY_RRF_K`、既定 60）で並べる。
- **スコアは距離のまま**。質問自身の検索で見つかった根拠は従来のスコアを保つ。変種だけが見つけた根拠は、その距離に
  `MULTI_QUERY_VARIANT_PENALTY`（既定 0.05）を足す。変種で遠い根拠が近く見えて、距離ガードをすり抜けることを防ぐため。
- 変種は候補を増やす（取りこぼしを減らす）ためのもので、最終的な順位は従来どおりその後の再ランクが決める。

## 確認

- トレース: `staged_retrieval.multi_query`（使った変種と deep か）、各根拠の `score_details.multi_query`
  （融合スコア、どの検索で見つかったか、変種だけか）。
- ノブ 4 つはノブ登録済みで、回答キャッシュのキーにも入る。評価は
  `python scripts/tenant_eval.py evaluate --profile ID --proposal mq --knob MULTI_QUERY_ENABLED=true --perturb`。
- 検索が 1 回から最大 5 回に増えるため、遅延と埋め込みの呼び出しも増える（変種は埋め込みをまとめない）。
