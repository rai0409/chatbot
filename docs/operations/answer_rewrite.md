# 抽出式の回答の書き換え（制約つき）

抽出式の回答は、文書の文をそのまま引用するので正確だが硬い。LLM の機能 `rewrite` が許可されているとき
（`LLM_ENABLED=true` と `LLM_FEATURES=rewrite`、`docs/operations/llm_policy.md`）だけ、引用した文を自然な言い回しに整える。
既定はオフで、`CHAT_GENERATION_MODE` が `extractive` のままでも使える（回答の骨格は抽出式、言い回しだけ LLM）。

## 仕組み

1. 抽出式の回答の箇条書き（`- 文 [S1]`）を、文だけ取り出して LLM に渡す。「意味・数値・固有名詞・否定・条件を変えず、
   新しい情報を足さず、同じ数の文を JSON の配列で返す」よう指示する。
2. 返った各文を、**元の文と照合して**、次をすべて満たすときだけ採用する（質問に含まれる語は許す）。

   | 規則 | 内容 |
   |---|---|
   | `numbers` | 数字が同じ（増減なし。全角は半角として比べる） |
   | `identifier` | 元に無い英字の語がない |
   | `katakana` | 元に無い 3 文字以上のカタカナ語がない |
   | `new_term` | 元に無い 3 文字以上の漢字の語がない |
   | `negation` | 否定・禁止を含む文はそのまま、含まない文は含まないまま |
   | `length` | 元の 0.5〜1.6 倍の長さ |

3. 規則を破った文は**元の文のまま**にする。箇条書きでない行と引用タグ `[S1]` は触らない。引用は元の文のものが残る。
4. 呼び出しが拒否（ポリシー）・失敗・形式不正（JSON の配列でない、数が違う）のときは、回答全体が元の抽出式のまま。

## 確認

- トレース `answer_rewrite`: `rewritten` / `kept_original` / `reason`（`ok` `no_bullets` `too_many_lines`
  `not_allowed:<層>` `error:<型>` `bad_output`）/ 破った規則の回数。**文の中身は載せない**。
- `/chat` と `/chat/stream` の、抽出式で根拠が十分なときの回答に適用される。LLM 生成の回答（`CHAT_GENERATION_MODE=llm`）には
  適用しない（そちらは 4-3 の根拠検証）。
- 効果は `tenant_eval.py evaluate` で、書き換えの有無を比べて確かめる（合格率と誤受理率が悪化しないこと）。

## 限界

- 規則は表層的な検査で、意味の保存を**保証するものではない**（たとえば条件の順序や助詞の違いは見えない）。
  だから採用は「元の文との差が小さいもの」に限り、迷えば元に戻す設計にしている。
- 1 回の回答で最大 8 文まで。それを超える回答は書き換えない。
