# SharePoint を文書ソースにする（Graph の差分取得）

SharePoint のドキュメントライブラリの 1 フォルダを、**ローカルのミラー**として保ち、ミラーを通常のフォルダとして
5-1（走査）と 5-2（差分の取り込み・大量変更ガード）に流す。つまり SharePoint 側で削除しても、コレクションに届くのは
同じ「ガード付きの経路」だけ。

## 登録

```
python scripts/sources.py add --id policies-sp --tenant tenant_a --kind sharepoint \
    --drive-id <ドライブID> --folder "/Shared Documents/Policies" --schedule 60 --by 担当
```

- ミラーは `SOURCES_DIR/mirror/<id>`。**`SOURCES_DIR` を `INGEST_ALLOWED_ROOTS` の中に置く**（取り込みがそこから読むため）。
  そうでなければ登録時に拒否する。
- 書き込み先は他のソースと同じステージング収集（`src-<id>`）。配信中のコレクションには書かない。

## 差分取得

- Graph の差分（delta）は、ドライブの**ルートでのみ**使える。そのためドライブ全体の差分を読み、設定したフォルダに絞る
  （フォルダの外の項目は無視。フォルダの外へ移された項目は削除として扱う）。
- 初回は差分リンクが無く、全件を列挙する。`@odata.nextLink` のページを追い、最後の `@odata.deltaLink` を次回のために保存する
  （保存先 `SOURCES_DIR/state/<id>.sharepoint.json`。項目 ID → ミラー内のパスと署名も持つ。削除の通知は ID しか持たないため）。
- **HTTP 410**（差分リンクの期限切れ）は、最初から全件を列挙し直し、ライブラリに無くなったファイルをミラーから消す。
- 429 / 503 / 504 は再試行する（`Retry-After` に従い、1 回の待ちは最大 60 秒、3 回まで）。

## ミラーに入るファイル

- 対応する形式（変換器の対応形式）のみ。隠し・一時ファイル（`.`始まり、`~$`）、`INGEST_MAX_FILE_BYTES` 超は取らない。
- **パスはミラーの外に出られない名前だけ**: `..`、絶対パス、`\`、制御文字を含むものは取らない（`unsafe` として数える）。
- サイズとハッシュ（なければ更新時刻）が同じファイルは、再ダウンロードしない。名前変更・移動は古いコピーを消す。

## 認証（読み取り専用）

- `SHAREPOINT_ACCESS_TOKEN`（用意したトークン）、または `SHAREPOINT_TENANT_ID` / `SHAREPOINT_CLIENT_ID` /
  `SHAREPOINT_CLIENT_SECRET`（クライアント資格情報でトークンを取得し、期限の少し前までメモリ内に保持）。
- アプリには、**そのライブラリを読める最小の権限**（サイト単位の付与など）だけを与える。シークレットはファイル・ログ・
  エラーメッセージに出さない（エラーには HTTP の状態だけを書く）。
- アプリの登録と権限の付与は、利用者側の作業（コードでは代替できない）。

## 限界

- 実際の SharePoint には接続して**いない**。通信は差し替え可能な関数の後ろにあり、テストは偽の応答で動かしている。
  実環境では、最初に小さなフォルダで走査（`scan`）と `plan` を確認してから定期実行にする。
- ファイルはメモリに読み込んでから書く（上限は `INGEST_MAX_FILE_BYTES`、既定 50MB）。
- 権限（誰がどのファイルを見られるか）は取り込まない。取り込んだ文書は、そのテナントの利用者全員が検索できる。
