# 管理コンソール（`/console/`）

React（TypeScript）で作った管理画面です。ビルドした静的ファイルを Web API が配信します（`webui/README.md`）。従来の管理画面（`/admin/...`）も当面残り、
それぞれのナビに「新コンソール」へのリンクがあります。**画面の操作と文言は、従来の画面と同じ意味にそろえてあります。**

## 画面に共通の決まり

- どの読み込みも、**読み込み中・エラー（再試行つき）・空（次にすることを書く）・成功**の 4 つの状態を持つ。
- 変更は、実行中はボタンを無効にし、結果を表示し、**衝突（409）と権限なし（403）を分かる言葉で示す**。理由が要る操作には理由の入力を求める。
- 削除・取り消しなど戻しにくい操作は、確認を挟む。
- 提案・承認・判定・版の有効化のように人が責任を持つ操作では、**操作する人の名前**を求める（ブラウザに記憶できる）。
- 文言は、画面ごとのカタログ（`webui/src/i18n/`）にまとめてあり、コードに埋め込まない。サーバーの理由コードは、カタログを通して日本語で表示する。
- キーボードで操作でき、表には見出しの関連づけがあり、色だけで意味を伝えない。幅の狭い画面でも使える。

## 従来の画面との違い（意図したもの）

- 従来の画面にあった「管理トークン（任意）」の入力欄は、ありません。コンソールは管理者のセッションと CSRF トークンで認証します。
- ダッシュボードの自動更新（従来は 30 秒ごと）は、今は入っていません（画面を開き直すか、再読み込みで更新）。

## 回答画面（`/chat-ui`）

- AI による回答の作成が使えないとき（LLM のブレーカーが開いている）、画面の上に**帯**を表示します（「現在、AI による文章生成は利用できません。登録文書の原文の抜粋を表示しています。」）。
  サーバーは理由コードだけを返し（`GET /system/status`）、ホスト名やモデル名は返しません。60 秒ごと、および回答のたびに確認します。
- その回答自体にも、「AI による文章生成が利用できなかったため、文書の原文の抜粋を表示しています。」という注記が付きます（`service_notice`）。
- 回答画面は従来の HTML のままです（React 化は、この範囲に入れていません）。

## まだ確認していないこと

実際のブラウザでの表示確認、利用者試験、実環境（実データ・実 LLM・実 OIDC）での動作は未実施です。画面のテストは jsdom（ブラウザの模擬）での確認です。
